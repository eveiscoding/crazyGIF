# 鬼畜表情包 Web V1 · PRD

更新：2026-11-04。原计划微信小程序，现改为从零建设的手机优先纯前端 Web 应用，优先 GitHub Pages。

## 产品目标

用户在手机上用一张照片完成“导入 → 获取透明主体 → 选模板 → 调整 → 预览 → 下载或保存表情包”。默认示例支持零上传体验。第一优先级是可导出可分享的完整闭环。

## 范围与约束

React + TypeScript + Vite。无微信小程序框架、后端 API、云函数、对象存储、数据库。图片解码、抠图、蒙版、预览和编码均在浏览器中。静态托管仅提供程序文件，AI 首次下载第三方模型。无遥测和素材上传。

## 用户流程与验收

1. 进入即有本地绘制示例，可播放暂停并直接导出。
2. 从相册选择 PNG/JPEG/WebP；透明 PNG 保留透明通道并可直接使用；非法或超限文件显示错误且不覆盖旧素材。
3. 可点击 AI 自动抠图，首次才加载模型；显示分文件下载进度、成功和失败状态。失败后可以继续手工处理。AI 不作为基本导出闭环的前置条件。
4. 手动精修提供套索保留、橡皮擦、恢复原图画笔、撤销重做。套索松手闭合，保留蒙版与圈选区域交集；恢复刷恢复原始像素的可见性。
5. 模板为疯狂摇头、精神蹦迪、旋转升天、抽搐抖动，支持速度与强度。
6. 调整主体大小、位置、角度、背景、文案、文字大小与颜色。预览与导出使用同一渲染器。
7. 默认导出 320×320、12fps、2 秒（24 帧）无限循环 GIF，也可选 1.5 秒（18 帧）。PNG 封面为第 0 帧。GIF 延时按 80/90ms 分配，平均 12fps；GIF 只支持二值透明。
8. GIF 用 Worker 编码，逐帧背压，显示进度、允许取消，主界面保持响应。结果显示文件类型、大小、预览、下载和系统分享入口。

## 移动端要求

最小布局宽度 320px，编辑区域可滚动，底部导出按钮考虑安全区。画布支持 Pointer Events 触控、pointer capture 和取消回滚。画布区域禁止浏览器滚动手势，页面其他区域保持正常滚动；提供数值位移以替代精确拖动。字体使用系统字体，避免网络字体阻塞。遵循减少动态效果偏好，默认暂停动画。

优先验收 iOS Safari、Android Chrome、iOS/Android 微信内置浏览器。AI 在设备内存或 WASM 能力不足时允许失败并说明替代方式；透明 PNG、手工和导出应独立可用。无法真机实测的项目必须标“待实测”。

## 不在本期

登录、作品库、云同步、上传分享链接、服务端推理、付费、自动发送微信、视频输入/输出、多人协作、长期草稿、任意分辨率导出。

## 开发闭环

- P0：示例 → 四模板 → 统一 Canvas → Worker GIF / PNG → 结果保存。
- P0：真实图片 → 透明通道 → 手动蒙版编辑 → 动画导出。
- P1：按需 AI、失败降级、移动端交互完善、许可证与公开源码入口。
- 发布：构建和编码验收 → GitHub Pages 自动部署 → 实际站点检查 → 真机矩阵记录。

## 成功指标

所有四模板完成本地 GIF 闭环，18/24 帧可解码、320×320、时长与循环标识正确；初次打开不请求 AI 模型；素材无外发请求；移动端无水平溢出。性能实测应记录机型、系统、浏览器、网络、模型冷/热启动耗时和峰值问题，不预填性能承诺。
